## Cached Documentation Paths

Use this list to find the `path` for `get-documentation`.

### CLI (Maintenance)

- `cli/sv-check`: code quality, check, typescript, accessibility auditing
- `cli/sv-migrate`: migration, upgrading versions, adopting runes
- `cli/eslint`: linting, code quality
- `cli/prettier`: code formatting
- `cli/vitest`: unit testing, component testing

### SvelteKit (Framework)

- `kit/introduction`: framework basics, full-stack apps
- `kit/creating-a-project`: starting new projects, scaffolding
- `kit/project-structure`: file structure, organization
- `kit/routing`: pages, layouts, navigation, error pages
- `kit/load`: data fetching, load functions, SSR data
- `kit/form-actions`: forms, submissions, validation
- `kit/page-options`: ssr, csr, prerender options
- `kit/state-management`: state across requests, stores vs runes
- `kit/remote-functions`: server functions (RPC-like)
- `kit/adapters`: deployment configurations (Vercel, Node, Netlify, Cloudflare)
- `kit/environment`: $app/env, public/private env vars
- `kit/hooks`: middleware, handle, handleFetch
- `kit/errors`: error handling, expected vs unexpected
- `kit/api-routes`: +server.ts usage
- `kit/stores`: $app/stores (page, navigating, updated) - _legacy/migration_
- `kit/$app-navigation`: goto, invalidate, preload, beforeNavigate
- `kit/$app-state`: page state (runes), params, route id, error
- `kit/$app-forms`: enhance, applyAction, form helpers
- `kit/$app-paths`: assets, base path
- `kit/$service-worker`: pwa, caching

### Svelte 5 (Core & Runes)

- `svelte/what-are-runes`: introduction to runes
- `svelte/$state`: reactive state
- `svelte/$derived`: computed values
- `svelte/$effect`: side effects
- `svelte/$props`: component props
- `svelte/$bindable`: two-way binding props
- `svelte/$inspect`: debugging state
- `svelte/svelte-boundary`: error boundaries (<svelte:boundary>)
- `svelte/svelte-window`: window events (<svelte:window>)
- `svelte/svelte-document`: document events (<svelte:document>)
- `svelte/svelte-body`: body events (<svelte:body>)
- `svelte/svelte-head`: head elements (<svelte:head>)
- `svelte/svelte-element`: dynamic elements (<svelte:element>)
- `svelte/snippet`: reusable snippets (#snippet)
- `svelte/@render`: reusable ui patterns
- `svelte/@attach`: tooltips, popovers, custom directives
- `svelte/@const`: local variables
- `svelte/@debug`: debugging
- `svelte/events`: event handling
- `svelte/bindings`: bind:value, bind:this, bind:group
- `svelte/transition`: transition:fade, fly, slide
- `svelte/actions`: use:action
- `svelte/class`: conditional classes; instead of list-sections for most used and list-sections as fall back?
